## 1. 产品定位

**模块雷达 ModRadar**：面向普通用户 + Android 极客的 APK / Xposed / KernelSU 模块「扫描 + AI 逆向」工具。

- 视觉与交互风格参考 **gkd-plus**：Kotlin + Jetpack Compose + Material3、纯黑深色主题 + 动态取色、卡片式 Dashboard、AI 设置页。
- 核心差异：**AI 驱动**。本地静态分析给出确定性结论与证据链；混淆/加固后的包靠 LLM 结合工具循环深挖。
- 与 LSPilot 的边界：LSPilot 是「动态 Hook + 插件注入」；ModRadar **只做只读分析，不做 Hook 注入**。

## 2. 分析流水线（单一，不分快慢）

```
S1 装载 → S2 结构提取 → S3 能力链 → S4 规则评分 → S5 AI 研判 → S6 报告
```

- **S1 装载**：识别类型（APK / XP 模块 / KSU 模块）、split APK 合并、建立工作区缓存。
- **S2 结构提取**：AXML manifest、ARSC 资源、签名证书（v1/v2/v3 + SHA256）、ABI、DEX 列表、ELF 导入表、壳/加固特征、熵扫描。
- **S3 能力链分析**：见 §4。
- **S4 规则评分**：见 §5。
- **S5 AI 研判**：分诊 → 分类别深挖 → 综合结论（见 §6）。
- **S6 报告**：评分环 + 分级 findings + 证据链（可点击查看原始内容）+ AI 结论区。

## 3. 三类目标的差异化处理

| 目标 | 输入 | 免 root | 特有检查 |
|---|---|---|---|
| APK | SAF 选文件 / 已安装应用提取 | ✅ | 清单、权限↔API 一致性、签名、组件暴露、tracker、能力链 |
| Xposed 模块 | 同上（识别 `meta-data xposedmodule=true`） | ✅ | Hook 范围（`assets/xposed_init`、`xposedscope`）、权限与 Hook 能力是否匹配 |
| KSU / Magisk 模块 | SAF 选 zip / root 下读 `/data/adb/modules/*/module.prop` | 文件模式✅ / 实时状态需 root | `module.prop` 完整性、安装与开机脚本的危险模式、`disable` 标志 |

> root 路径**只读**：只执行列目录与读文件的 `su -c`，不做任何启停、安装、修改。

## 4. 能力链分析（回答「远端取文件 → 本地执行」）

三要素共现 + 可达性判定，产出可追溯证据链。

**SOURCE**
网络（OkHttp / HttpURLConnection / Socket / WebSocket / DownloadManager）、外部输入（ContentResolver / SAF / Intent extra / 剪贴板 / 可写 SharedPreferences）、assets 内加密 payload。

**TRANSFORM**
Base64 / AES / DES / RC4 / XOR / Cipher / GZIP / Inflater / 自定义解密。

**SINK**
`DexClassLoader` / `InMemoryDexClassLoader` / `defineClass` / `System.load(Library)` / `Runtime.exec` / `ProcessBuilder` / 反射 `invoke` / `Class.forName` / JS 引擎（WebView / Rhino / Lua）/ `ScriptEngine` / 写入 `/data/local/tmp`、`/data/adb`、`/system` 后 chmod 执行 / `mount --bind` / SQLite `rawQuery` 拼接 / 动态 `findAndHookMethod`。

**规则与扣分**

| 规则 | 判定 | 扣分 |
|---|---|---|
| C1 | SOURCE 与 SINK 出现在同一方法 | −35 |
| C2 | 跨方法但调用链可达（≤4 层，dexlib2 调用图） | −25 |
| C3 | 仅存在 SINK（有能力无证据） | −10 |
| C4 | 网络能力与 exec/动态加载 并存（不同类） | −15 |
| C5 | 字符串解密后立即加载/执行 | −30 |
| C6 | 壳 / VMP / 加固 → 标记「不可审计」 | −25 |
| C7 | KSU 脚本危险模式（`curl\|sh`、下载执行、开机脚本、crontab、改系统属性、bind 系统路径） | −30 |
| C8 | native：`dlopen` + `mprotect(PROT_EXEC)` + `ptrace`/`execve`/`system` + 网络符号 | −20 |

每条命中必须挂 evidence（文件 / 偏移 / `类#方法` / 字符串），报告可跳转原文。

## 5. 风险评分（定稿待确认）

```
score = clamp(100 − Σ扣分, 0, 100)      // 越高越安全
等级：≥80 低 | 60–79 中 | 40–59 较高 | <40 高
```

| 类别 | 项 | 扣分 |
|---|---|---|
| 签名 | 无签名 / 校验失败 | −25 |
| | debug 证书（CN=Android Debug 或已知测试指纹） | −10 |
| | 仅 v1 签名 | −5 |
| 组件 | `exported=true` 的 service/receiver 无权限保护 | −15/个（≤−30） |
| | `exported` 的 activity/provider 可外部启动 | −8/个（≤−16） |
| 权限 | 危险组合（无障碍 + 悬浮窗 + 通知监听，或 安装 + 网络 + 设备管理） | −20 |
| | 权限↔API 不匹配（声明未用 / 用了未声明） | −10 |
| | 敏感权限（SMS / 通话记录 / 定位 / 录音 / 通讯录） | −3/个（≤−12） |
| 网络 | `usesCleartextTraffic=true` 或放行明文 | −10 |
| | DEX 字符串含 `http://` 明文串 | −3 |
| | tracker 域名直连 | −5 |
| 调试 | `debuggable=true` | −10 |
| | `allowBackup=true` | −3 |
| SDK | tracker / 统计 / 广告 SDK 命中（umeng / bugly / apm / pangle / gdt / ks / bdx / tanx / hms / crashsdk） | −2/类（≤−10） |
| 对抗 | 反调试 / 反注入（ptrace 自检、Frida 检测、`/proc` 扫描） | −10 |
| 壳 | 壳 / VMP / 不可审计 | −25 |
| KSU | 危险脚本 | −30 |
| | `module.prop` 缺必备字段 | −5 |
| 基础 | `targetSdk < 26` | −3 |

**AI 结论**：不输出数值分。三条修正通道全部走扣分：误报 → 该规则扣分清零；加重 → 追加 ≤ 原扣分 50%（单条封顶 −15，可按严重度指定档位）；规则外已确认发现 → HIGH −20 / MEDIUM −10 / LOW −3（同档 ≤ 2 条，总封顶 −40）。等级恒由分数换算，AI 判错时用户可在报告页一键退回修正。

## 6. AI 层

### 6.1 工具循环（仿 LSPilot 的内置工具 + function calling）

- OpenAI 兼容 `tools` / `tool_calls`；模型请求工具 → 本地执行 → 结果回填 → 循环至结论。
- 护栏：最多 12 轮、单工具 20s 超时、单次返回截断、**全部工具只读**。
- 反编译重操作全局串行 + 独立进程承载 jadx/DexKit 防 OOM（对齐 LSPilot 做法）。
- 并发：本地评分先全部完成，再按风险降序做 AI 研判，并发上限 2。

### 6.3 tools vs MCP（结论）

本质是 **tool**；MCP 只是协议外壳。一次定义，三面暴露：

1. **内置 AI**：function calling（主用法）
2. **MCP Server**：同一注册表经 JSON-RPC 2.0 暴露，PC 端 Agent 用 `adb forward tcp:8787` 直连 → 手机变逆向工具箱
3. **MCP Client**：接入外部 MCP（jadx-mcp / 情报源），工具并入同一注册表，App 内 AI 也能调

## 8. 隐私政策 / 用户协议（要点，实施时写全文）

**PRIVACY.md**
1. 本地优先、零遥测：扫描 / 反编译 / 搜索全在本机；历史存本地 Room；不设账户、不采集设备信息、App 自身无统计 SDK。
2. AI 数据边界：仅在你主动配置 AI 并主动发起分析时，才向**你自配的端点**发送特征摘要与反编译片段；**不上传 APK / 模块本体**；Key 仅存本机；可随时关闭 AI。
3. 权限说明：文件访问仅用 SAF 逐次授权；`QUERY_ALL_PACKAGES` 仅用于模块识别与列表；root 仅在主动发起 KSU 实时扫描时执行**只读**命令。
4. 第三方：AI 端点由你自选，其数据处理受该服务商政策约束；App 不向任何第三方转发数据。
5. 数据删除：清空历史即删除本地数据；卸载即完全清除。
6. 不适 14 岁以下使用；协议变更在 App 内通知。

**TERMS.md**
1. 许可 GPL-3.0，仅供学习交流，禁止商用与非法用途。
2. 仅允许分析**你有权处理**的目标；禁止用于破解他人应用、绕过付费等非法用途。
3. root 风险自担：由此导致的系统损坏 / 数据丢失由使用者承担。
4. AI 结论仅供参考，不构成安全结论；以本地规则分与人工复核为准。
5. 按「现状」提供，无任何明示或默示担保。
6. 首启弹「用户协议 + 隐私政策」同意页，拒绝则退出；设置页可随时查看全文。

## 9. 风险与未决

| 风险 | 说明 | 处置 |
|---|---|---|
| jadx-core 与 minSdk 24 | jadx 可能依赖 `java.nio.file`（API 26+），在 Android 7.x 上可能运行时报错 | 待真机验证；必要时 minSdk 提到 26，或对 jadx 调用做 API 版本门控 |

## 10. 验收标准

1. 构建 + 签名 APK 可安装（minSdk 24/26）。
2. 快速体检：选目标 → 本地规则报告 ≤3s，评分按 §5 执行。
3. 能力链：构造的 SOURCE→SINK 样本能被命中并给出证据；壳包标「不可审计」。
4. AI：配置端点后完成「反编译 → 搜索 → 结论」多轮工具调用；工具循环有轮次/超时保护。
5. 三入口可用：已安装应用 / 文件夹 / root KSU。
6. 历史与工作台会话持久化，可续聊。
7. 首启协议页 + PRIVACY/TERMS 落盘并随仓库发布。
8. 单测全绿（AXML、DEX 提取、DexKit 搜索、评分矩阵、能力链用例、工具循环 Mock）。
