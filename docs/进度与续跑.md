### P1 — S3 能力链分析（`task/stages/ChainStage.kt`）✅ 已完成

实现内容：`ChainStage.kt`（dexlib2 指令级扫描 + 调用图 ≤4 层可达）+ `ApiSignatures.kt`（SOURCE/TRANSFORM/SINK 分类表）

以下为原始设计说明（供后续调整参考）：
用 dexlib2 加载 APK 内 `classes*.dex`，产出 `S3.json` + `CapabilityChain`：

- **SOURCE**：OkHttp / HttpURLConnection / Socket / WebSocket / DownloadManager / ContentResolver / SAF / Intent extra / 剪贴板 / 可写 SharedPreferences
- **TRANSFORM**：Base64 / AES / DES / RC4 / XOR / Cipher / GZIP / Inflater
- **SINK**：DexClassLoader / InMemoryDexClassLoader / defineClass / System.load(Library) / Runtime.exec / ProcessBuilder / 反射 invoke / Class.forName / WebView.evaluateJavascript / Rhino / Lua / ScriptEngine / 写 /data/local/tmp|/data/adb|/system 后 chmod 执行 / mount --bind / SQLite rawQuery 拼接 / 动态 findAndHookMethod
- **规则**（见计划.md §4）：C1 同方法 −35、C2 调用链可达 ≤4 层 −25、C3 仅 SINK −10、C4 网络+exec 并存 −15、C5 解密后加载 −30、C6 壳/VMP 不可审计 −25、C7 KSU 脚本 −30、C8 native 导入组合 −20
- 每条命中必须产出 **evidence**（文件 / 偏移 / `类#方法` / 字符串）
- 实现要点：先扫 `const-string` 与 invoke 指令建立 `方法 → API 集合`；再建 `方法 → 被调用方法` 调用图做 ≤4 层可达；大 APK 要限流与 `ctx.checkPause()`
- 完成后在 `Runners.kt` 注册，并让 `ToolRegistry.capabilityChainTool()` 返回真实结果

## 6 产品口径（别改错方向）

- 定位：**只读分析工具**，不做 Hook 注入（与 LSPilot 的边界）。
- AI 是主打：本地静态分析给确定性证据，混淆/加固靠 AI + 工具循环深挖。
- **AI 结论不计入总分**；仅在引用本地已核验证据时可升级等级，永不降级。
- 数据边界：仅上传特征摘要与反编译片段，**不上传 APK 本体**；不配置 AI 时本地功能完整可用，报告标「未完成 AI 研判」。
