# 后台执行 · 断点续跑 · 暂停期对话（实现说明）

> 对应已批准方案。本文件记录**已落地**的实现细节与验证结果。

## 1 后台执行

**前台服务** `service/AnalysisService`
- 类型 `dataSync`，Manifest 声明 `android:foregroundServiceType="dataSync"`，权限 `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_DATA_SYNC`
- 常驻通知 `service/AnalysisNotifications`：渠道 `modradar.analysis`（`IMPORTANCE_LOW`）、进度条、`setOnlyAlertOnce`、内嵌「暂停/继续」与「取消」两个 action
- **Android 15+ dataSync 6 小时上限**：覆写 `Service.onTimeout(startId, fgsType)`，置暂停位并提示「已达系统时长上限，可稍后继续」，checkpoint 由流水线在安全点落盘
- 启动时机：仅在用户点击「开始分析/继续分析」后从可见 Activity 启动；`promoteToForeground` 捕获异常并降级为「仅前台分析」（Android 12+ 后台启 FGS 受限）
- `START_REDELIVER_INTENT`：进程被杀后系统可重投 intent

**保活引导** `service/BackgroundGuard` + `service/VendorAutostart` + `ui/KeepAliveScreen`
| 步骤 | 检测方式 | 跳转 |
|---|---|---|
| 通知权限 | `checkSelfPermission(POST_NOTIFICATIONS)`（13+） | 运行时请求 |
| 省电优化豁免 | `PowerManager.isIgnoringBatteryOptimizations` | `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`，失败回退 `ACTION_IGNORE_BATTERY_OPTIMIZATION_SETTINGS` |
| 后台运行白名单 | 无 API → 显示「需手动」 | 厂商页面（12 个候选，`getActivityInfo` 逐个探测），无命中回退应用详情页 |
| 锁定应用 | 无 API → 显示「需手动」 | 图文步骤 |
- 额外检测 `ActivityManager.isBackgroundRestricted`，受限时给出提示
- 厂商跳转依赖 `QUERY_ALL_PACKAGES`（已在 Manifest 声明）

## 2 断点续跑

**存储分层**
- `filesDir/tasks/<taskId>/`：checkpoint 与结构化产物（`S1.json` / `S2.json` …）——**不用 cacheDir**，避免被系统清理
- `cacheDir/tasks/<taskId>/`：大体积中间产物，可重算

**提交协议** `task/ArtifactStore.writeAtomic`
```
写 <name>.tmp → flush → fd.sync() → rename 到 <name> → 返回 sha256
```
先落盘（原子 rename）后落库，任何时刻中断都不会留下半截文件。

**状态机** `task/Pipeline`
- 阶段 `S1 装载 → S2 结构提取 → S3 能力链 → S4 评分 → S5 AI 研判 → S6 报告`
- 续跑：`completedStages` 内的阶段直接跳过（`Pipeline.nextStage`）
- 暂停：仅在安全点抛 `PauseSignal`（阶段内通过 `ctx.checkPause()` 主动让出），被打断阶段保持非 DONE，续跑时重入
- 未实现阶段（当前 S3–S6）：任务保持 `PAUSED`，不伪造完成
- 并发：同一时刻只跑一个任务（服务单实例 + `job?.cancel()`）

**数据模型**（Room `modradar.db` v1）
`tasks` / `checkpoints(taskId,stage)` / `chat_sessions` / `chat_messages`

## 3 暂停期对话（部分数据模式）

- `ai/ChatEngine` **与流水线解耦**：只读已完成阶段的产物，暂停 / 失败 / 未跑完都能进入
- **工具门控** `ai/tools/ToolRegistry`：每个工具声明 `requiredStages`，缺阶段返回
  `{"error":"data_not_ready","completed":"S1,S2","required":"S3","hint":"…"}`
  —— 保证模型不会把「未扫描」当成「未发现」
- **Prompt** `ai/prompts/Prompts`：P0 铁律（不臆造、区分已确认/有嫌疑/未扫描）+ P8 部分数据模式（列出已完成与未完成阶段、禁止整体安全结论）
- 工具循环：最多 12 轮，超出则报「已达轮次上限」
- UI：`ui/WorkspaceScreen` 顶部横幅「分析暂停于 S3 能力链分析 · 结论基于部分数据」+「继续分析」按钮

## 5 已知边界

- 厂商白名单与最近任务锁定**无法检测**，只能引导
- 空闲「常驻通知保活」未实现（需 `specialUse` FGS，耗电且受系统限制），当前仅分析期常驻
- S3–S6 未实现，因此任务会停在 S3 并保持 `PAUSED`——这正是部分数据模式的真实场景
